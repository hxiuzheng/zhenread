# 时间轴覆盖对比

帧读的 `timeline` 包把每条轨道上的区间转换为起点和终点事件，按轨道与时间排序，同一位置先合并计数变化，再处理下一个时间段。它只输出两版计数不同的范围，并合并相邻且旧计数、新计数分别相同的片段。N 是两版输入的区间总数，时间复杂度为 O(N log N)，额外空间为 O(N)。输出顺序固定为轨道名、起点。

## 示例

从仓库根目录运行 `moon run cmd/main -- coverage examples/timeline/NAME-before.json examples/timeline/NAME-after.json`，替换表中的 NAME。每个例子都有预期差异，退出码为 1。

| NAME | 输入数据 | 可核对结果 |
| --- | --- | --- |
| `edit` | 剪辑轨以帧为单位，比较剪辑与旁白两条轨道 | 视频缺失 `[48,54)`，覆盖 1→0，旁白轨无差异 |
| `booking` | 用分钟表示同一设备的两次预约 | 调整预约起点后，`[585,600)` 从 1 次预约变为 2 次 |
| `labels` | 用毫秒表示语料标注的类别覆盖 | 语音标注拆分后覆盖一致，背景声在 `[2500,3500)` 从 0→1 |

输入是 JSON 数组，`[]` 表示空轨道集合。端点用十进制字符串保存完整的 64 位整数精度。输出中的 `before` 和 `after` 也以十进制字符串表示计数。

```json
[{"track":"video","start":"48","end":"54","before":"1","after":"0"}]
```

## 选择对比方式

- 用 `coverage` 判断某条轨道在某段时间内有几份内容，以及两版计数是否相同。两版须使用相同时间单位、原点和轨道命名。区间必须满足起点小于终点。
- 用 `compare` 追踪 WebVTT 中某条字幕的文字和时间变化。相同覆盖下的内容替换属于这类问题。
- 用 `check` 诊断单份字幕的时间、行长和阅读速度。CLI 的 `coverage` 可直接读取字幕，不依赖字幕 ID。与 JSON 混合对比时，JSON 须使用毫秒和 `subtitles` 轨道名。

覆盖对比适用于版本快照。若两个区间变化后在每个时间点仍有相同的活动数量，两版结果相同。任务调度、设备分配和媒体语义由调用层处理。

## 验证

运行 `moon run tools/verify.mbtx` 检查三个 JSON 样例的完整输出、字幕输入和错误退出码。库测试还将扫描结果和逐点计数对照，覆盖 96 组输入及同点边界、并发、轨道隔离和 64 位坐标。

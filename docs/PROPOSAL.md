# 申报事实与场景核对

按章程 §5.1，参赛者应亲自撰写一页 Markdown 申报书。写作时可核对下列项目事实、复现场景和证据，并结合本人观察说明痛点与技术取舍。

| 申报字段 | 可核对事实 |
| --- | --- |
| 名称、方向和仓库 | 帧读 ZhenRead · 内容数据处理与开发者工具 · [hxiuzheng/zhenread](https://github.com/hxiuzheng/zhenread) |
| 复用范围 | MoonBit 库供应用复用，命令行供课程、视频和本地化交付流程运行。规则结果有源行号和结构化数据 |
| 已有基础与新增 | 单文件检查支持 SRT/WebVTT。相对公开基线 `89cb5cc`，新增两版 WebVTT 的稳定 ID 回归、并排报告、解析兼容和报告防覆盖 |
| 来源与定位 | 原创实现，参考格式规范。已有 MoonBit 项目覆盖部分单文件检查，相关功能重合与修订回归边界见 [来源说明](SOURCES.md) |
| 交付边界 | 修订比对依赖显式唯一 ID，时间容差为毫秒。编辑需要人工判断文字改动是否符合原意、字幕是否与声音同步 |
| 验证与有效提交 | 运行 [验收复现步骤](ACCEPTANCE.md)，在正式申报前核实 GitHub 公开提交和本赛期贡献 |

| 使用场景 | 输入、操作和结果 |
| --- | --- |
| 课程字幕修订复核 | 输入带相同 cue ID 的审定版和待发布版，运行 `compare` 并打开 HTML。编辑可看到术语改字、时间漂移、删除和新增，并回到两版对应行 |
| 短视频交付门禁 | 将导出的 SRT 或 WebVTT 输入 `check --strict`。示例中的短时、超速和重叠会返回 1，交付流程可暂停等待人工处理 |
| 培训平台导入前排错 | 用 `check` 检查带错误时间行的 WebVTT。报告指出错误块的源行号，并保留后续可解析字幕，便于修正后再导入 |

参赛者需亲自补充实际遇到的字幕问题、为什么采用稳定 ID、可承担的交付范围、报名方向及组委会要求的本人信息。

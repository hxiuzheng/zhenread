# 申报事实与场景核对

按章程 §5.1，参赛者应亲自撰写一页 Markdown 申报书。写作时可核对下列项目事实、复现场景和证据，并结合本人观察说明痛点与技术取舍。

| 申报字段 | 可核对事实 |
| --- | --- |
| 名称、方向和仓库 | 帧读 ZhenRead · MoonBit 时间轴分析与版本回归 · [hxiuzheng/zhenread](https://github.com/hxiuzheng/zhenread) |
| 复用范围 | 独立的 `timeline` 包接收两份带轨道名和整数端点的区间集合，输出覆盖数量改变的时间段。调用者可用帧、分钟或毫秒，两版单位与原点一致 |
| 已有基础与新增 | 相对 `2ff2654`，新增扫描线库、JSON CLI 及字幕覆盖适配。字幕质量检查和 WebVTT 按 ID 修订比对为已有功能 |
| 来源与定位 | 原创实现。对照动态区间查询、双时态记录、ELAN 标注工具和字幕质检生态，见[来源说明](SOURCES.md) |
| 交付边界 | 通用对比关心每轨覆盖数量变化。同数量下的字幕文字变更由 WebVTT 修订命令定位 |
| 验证与有效提交 | 运行 [验收复现步骤](ACCEPTANCE.md)，在正式申报前核实 GitHub 公开提交和本赛期贡献 |

| 使用场景 | 输入、操作和结果 |
| --- | --- |
| 剪辑工程复核 | 两版按帧导出区间，`coverage` 定位视频轨丢失的第 48 至 54 帧区间，旁白轨保持一致 |
| 设备预约回归 | 两版按分钟导出设备预约，`coverage` 定位 `camera-a` 新产生的 15 分钟双重预约 |
| 语料标注复核 | 两版按类别与毫秒导出区间。原语音标注拆成相邻片段时覆盖一致，新增背景声范围单独报告 |
